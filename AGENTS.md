# Java

1. Setters and getters should not contain any logic besides copying values.
2. If a lambda can be replaced with a method reference, replace it.
3. Do not use `@Inject` on constructors; use field injection with `@Inject`.
4. Name an injected field after its class, with the first letter lowercased.
5. As an exception to the previous rule, always name an injected `Transaction` field `tx`.
6. If a record declaration contains no methods, do not put an empty line between the opening and closing braces. Keep
   the opening and closing braces on separate lines.
7. When parameters in a declaration or arguments in a call are arranged vertically, preserve that layout when adding
   new parameters or arguments: put each on its own line, not alongside an existing one.

## Documents

1. Keep all project documentation under `doc/`. Do not create documentation files in `docs/` or elsewhere.
2. Format all documents with a maximum line length of 120 characters.
3. `doc/architecture.md` is the entry point to the architecture documentation. Put detailed architecture descriptions
   in the most specific chapter under `doc/architecture/` and update the entry point when adding or renaming a chapter.
4. Architecture documentation describes the current implementation. Verify claims against code, configuration, and
   migrations; do not put implementation plans, rollout instructions, or historical behavior in these documents.
5. When a change alters component boundaries, data ownership, transaction boundaries, durable workflows, federation,
   or deployment requirements, update the affected architecture chapter in the same change.
6. Keep detailed wire fields in the public API specifications and exact database definitions in Flyway migrations.
   Architecture documents should explain their stable relationships and invariants and link to the source of truth.

# Database layer
 
1. doc/create_tables.sql is generated by a script, don't touch it.
2. @Column is not needed if the column name is the same as the field name, just converted to snake case. This conversion
   is done automatically.
3. In the DB, entry_revisions.deleted_at IS NOT NULL when and only when the revision is the current revision of
   the entry. In other words, the conditions `er.deleted_at IS NOT NULL` and `entry.current_revision_id = er.id` are
   equivalent.
4. In JPA repository interfaces, always write the DB queries explicitly.

# Public API

1. The difference between media files and media file owners is an implementation detail that is not exposed in the
   public API. A media file owner ID in the implementation is called a media file ID in the public API, and a media
   file ID in the implementation is called a media file hash in the public API.

# Web UI

1. Web UI is the built-in web interface of `moera-node`, intended for limited clients, search engines, and AI agents.
   It does not refer to the `moera-client-react` client application.

# Instant stories

1. Creation of stories in `Feed.INSTANT` must be initiated only by liberin receptors.
2. A liberin receptor must delegate this creation to a dedicated instant creator component that extends
   `InstantsCreator`; it must not construct or persist the story directly.

# Notification handlers

1. Notification handlers (methods annotated with `@NotificationMapping`) must not perform long-running operations
   or call remote APIs directly, including downloading avatars or other media. Delegate this work to jobs. Schedule
   persistent jobs with `Jobs.runAfterCommit` and the local node ID, keeping validation and short local operations in
   the handler.

# Other
 
1. In src/main/resources/messages.properties, place codes with the same 1st or 1st and 2nd components together. Place
   codes with 3 components first and codes with 2 components after them. Codes with only 1 component should be placed at
   the beginning of the file.
2. `Job.success()`, `Job.fail()`, `Job.retry()` always throw an exception, so there is no need to write `return` after
   them.
3. `UniversalContext` automatically puts liberins on hold during a transaction and commits them after committing the
   transaction, so don't add an external mechanism for this.
4. `UniversalContext.associate()` causes side effects that affect further execution of the whole thread. Avoid calling
   it in methods that are not semantically bound to a concrete job or background task.
5. Before downloading avatars with `mediaManager.downloadAvatar/downloadAvatars`, call
   `Contact.toAvatar(contactOperations.find(...), ...)` to fetch the avatar that is already downloaded.
